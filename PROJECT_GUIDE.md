### 2. Как устроен Фронтенд (Frontend)
Фронтенд построен по модульному принципу:
* **Интерфейс и стили (`Tailwind CSS`):** Адаптивный дизайн (Mobile-First от 360px до 4K мониторов). На мобильных устройствах автоматически включается удобная нижняя панель навигации (`BottomNav`), на компьютерах — полноценный верхний хедер с глобальным поиском.
* **Маршрутизация (`React Router v6`):**
  - Публичные страницы: `/login`, `*` (404).
  - Защищенные страницы: `/` (Каталог), `/listing/:id` (Детали), `/listings/new` (Создание), `/my-listings` (Мои товары), `/favorites` (Избранное), `/profile` (Профиль). Если неавторизованный пользователь попытается зайти по прямой ссылке, компонент `ProtectedRoute` перенаправит его на логин и запомнит страницу, чтобы вернуть обратно после входа.
* **Каталог и поиск:** Поиск работает с задержкой 300 мс (`useDebounce`), чтобы не перегружать память частыми запросами при наборе текста. Все фильтры (категория, состояние, мин/макс цена, сортировка) синхронизируются с URL-адресом браузера (можно скопировать ссылку с фильтрами и отправить другу).
* **Оптимистичный UI (`Optimistic Updates`):** При нажатии на «сердечко» (добавить в избранное) иконка загорается мгновенно без ожидания ответа сервера, обеспечивая максимальную плавность приложения.
* **Обработка картинок на клиенте:** Загружаемые фотографии автоматически сжимаются через HTML5 Canvas до 1024px, уменьшая размер в разы перед отправкой в базу.

### 3. Как устроен Бэкенд и База Данных (Backend & Database)
В качестве серверного решения используется **Serverless-архитектура на базе Google Cloud Firebase**:
* **Firebase Auth (Сервис аутентификации):** Управляет сессиями, шифрованием паролей, отправкой писем верификации и обменом токенов с Google OAuth.
* **Cloud Firestore (Облачная NoSQL база данных):** 
  - Данные хранятся в виде JSON-документов в двух коллекциях: `listings` (объявления) и `users` (пользователи).
  - При создании объявления генерируется уникальный идентификатор `item_<timestamp>_<random>`, а все поля предварительно очищаются от `undefined`, гарантируя целостность структуры.
* **Архитектурный паттерн «Адаптер» (`src/api/`):** Фронтенд ничего не знает о том, откуда приходят данные. Он просто вызывает методы интерфейса `api.getListings()`, `api.createListing()` и т.д. Если завтра потребуется заменить Firebase на Python FastAPI или Node.js, достаточно написать новый адаптер без изменения компонентов интерфейса.

## ЧАСТЬ 3. Быстрая шпаргалка к вопросам преподавателей

1. **Вопрос:** *«Где физически хранятся данные?»*
   - **Ответ:** *«В облачной NoSQL базе данных Google Cloud Firestore в регионе Европы. Данные синхронизируются в реальном времени.»*
2. **Вопрос:** *«Почему на клиенте используется сжатие изображений?»*
   - **Ответ:** *«Студенты часто загружают фото с камер телефонов весом 5-10 МБ. Клиентский ресайз до 1024px уменьшает вес до ~150 КБ, экономя трафик пользователя и ускоряя загрузку каталога.»*
3. **Вопрос:** *«Что произойдет, если база упадет или пропадет интернет?»*
   - **Ответ:** *«Благодаря абстракции `ApiClient` интерфейс не крашится: компоненты перехватывают ошибки, отображают аккуратный Error State с кнопкой «Retry» и всплывающие уведомления Toast.»*
