# Deployment guide

Production stack for the Student Marketplace (React frontend + Spring Boot backend + PostgreSQL).

```
                Internet
                   │  80 / 443
                   ▼
        ┌─────────────────────┐
        │  frontend (Nginx)   │  serves the SPA, proxies /api/ to backend
        └──────────┬──────────┘
                   │ internal Docker network (backend:8080)
                   ▼
        ┌─────────────────────┐        ┌──────────────────┐
        │  backend (Spring)   │───────▶│  db (PostgreSQL) │
        └──────────┬──────────┘        └────────┬─────────┘
                   │                            │
              photos volume                pgdata volume
                                                 │
                                        ┌────────┴─────────┐
                                        │ db-backup (daily)│
                                        └──────────────────┘
```

Only the `frontend` container publishes ports. PostgreSQL (5432) and the backend (8080) are
reachable only from the internal Docker network, so they are never exposed to the internet.

## 1. What you need

| Requirement | Notes |
|---|---|
| Docker Engine 24+ with Compose v2 | `docker compose version` |
| A server with 2 GB RAM / 2 vCPU or more | backend + PostgreSQL + Nginx |
| A domain pointing to the server | e.g. `marketplace.kbtu.kz` (A record) |
| Ports 80 and 443 open | and 22 for SSH |
| Firebase project | the same one the frontend uses (`student-marketplace-1b107`) |

Repositories used by the compose file:

```
2kbtu/
├── BIS/                    # frontend (this repository), contains deploy/
└── student-marketplace/    # backend
```

`deploy/docker-compose.prod.yml` builds the frontend from `..` and the backend from
`../../student-marketplace`. Keep the two directories side by side, or edit the two `context:`
values.

## 2. Prepare the environment file

```powershell
cd deploy
Copy-Item .env.prod.example .env.prod
.\scripts\generate-secrets.ps1 -OutFile .env.prod
notepad .env.prod
```

On Linux/macOS:

```bash
cd deploy
cp .env.prod.example .env.prod
pwsh ./scripts/generate-secrets.ps1 -OutFile .env.prod
# or generate values manually:
#   openssl rand -base64 48
```

Fill in at least:

- `DB_PASSWORD`, `JWT_SECRET`, `ADMIN_PASSWORD` — generated by the script;
- `ADMIN_EMAIL` — the first administrator account;
- `FIREBASE_PROJECT_ID` — `student-marketplace-1b107`;
- `VITE_FIREBASE_API_KEY`, `VITE_FIREBASE_AUTH_DOMAIN`, `VITE_FIREBASE_PROJECT_ID`,
  `VITE_FIREBASE_APP_ID` — from Firebase console → Project settings → Your apps → Web app;
- `CORS_ORIGINS` — `https://<your-domain>` (only needed if the app is ever served from a
  different origin; the default stack is same-origin);
- `DOMAIN` — used by the documentation and TLS examples.

`JWT_SECRET` must be at least 32 characters, otherwise the backend refuses to start. This is
intentional: a short secret can be brute-forced.

`.env.prod` is in `.gitignore` and must never be committed.

Every compose command in this guide passes `--env-file .env.prod`, because Docker Compose
only loads a file named `.env` automatically. Without the flag the `:?` guards stop the start
with an explicit "set DB_PASSWORD in .env.prod" error instead of deploying with defaults.

## 3. Build and start

```bash
cd deploy
docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --build
```

First start takes a few minutes (Maven and npm dependencies are downloaded inside the build).

Check the state:

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml ps
docker compose --env-file .env.prod -f docker-compose.prod.yml logs -f backend
```

Expected:

- `db` — healthy;
- `backend` — healthy (`/actuator/health` inside the container);
- `frontend` — healthy (`/healthz`);
- `db-backup` — running.

Open `http://<server-ip>/` — the catalog should load.

## 4. HTTPS

The default `nginx/default.conf` listens on port 80 only. Enable TLS before exposing the site
to real users, otherwise passwords and Firebase tokens travel in clear text.

1. Obtain certificates for the domain. With Let's Encrypt on the host:

   ```bash
   sudo certbot certonly --standalone -d marketplace.kbtu.kz
   ```

2. Copy the certificate files into `deploy/nginx/certs/`:

   ```
   deploy/nginx/certs/fullchain.pem
   deploy/nginx/certs/privkey.pem
   ```

3. Use the HTTPS config instead of the HTTP one. Either copy it over the default file:

   ```bash
   cp nginx/https.conf.example nginx/default.conf
   ```

   or change the volume mount in `docker-compose.prod.yml` to
   `./nginx/https.conf:/etc/nginx/conf.d/default.conf:ro`.

4. Recreate the frontend container:

   ```bash
   docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --force-recreate frontend
   ```

5. Set `CORS_ORIGINS=https://marketplace.kbtu.kz` in `.env.prod` and restart the backend:

   ```bash
   docker compose --env-file .env.prod -f docker-compose.prod.yml up -d backend
   ```

The HTTPS config sends `Strict-Transport-Security`, redirects HTTP → HTTPS and enables
TLS 1.2/1.3. Renewal: `certbot renew` writes new files; restart the frontend container
afterwards.

## 5. Firebase console checklist

- Authentication → Sign-in method: Email/Password and Google are enabled (as needed).
- Authentication → Settings → Authorized domains: add `marketplace.kbtu.kz`.
- The backend verifies ID tokens against `FIREBASE_PROJECT_ID`; it needs no service account
  key. Keep it that way: a service account JSON on the server is a bigger secret than a project ID.
- If `ALLOWED_EMAIL_DOMAIN=kbtu.kz`, only `@kbtu.kz` accounts can register.

## 6. Backups and restore

Database dumps are written by the `db-backup` container to `deploy/backups/db/`
(daily, kept 14 days by default; weekly/monthly copies are also kept).

Uploaded photos live in the `photos` Docker volume. Back them up from the backend repository:

```bash
# on the host, with the stack running
cd /path/to/student-marketplace
./scripts/backup-photos.sh /mnt/backups/marketplace
```

Restore a database dump:

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml stop backend
docker compose --env-file .env.prod -f docker-compose.prod.yml exec -T db \
  psql -U marketplace -d marketplace < backups/db/<file>.sql
docker compose --env-file .env.prod -f docker-compose.prod.yml start backend
```

Restore photos:

```bash
docker run --rm -v student-marketplace_photos:/data \
  -v /mnt/backups/marketplace:/backup alpine \
  tar xzf /backup/photos-YYYY-MM-DD.tar.gz -C /data
```

Test a restore on a staging machine before you need it in production.

## 7. Update / rollback

```bash
cd deploy
# update the sources of both projects (git pull, or copy a new release)
git -C .. pull
docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --build
```

Rollback: check out the previous commit in both repositories and run the same command.
Database migrations are forward-only (Flyway); take a dump before an update that adds a
migration.

## 8. Operations

```bash
# status and resource usage
docker compose --env-file .env.prod -f docker-compose.prod.yml ps
docker stats

# logs (follow)
docker compose --env-file .env.prod -f docker-compose.prod.yml logs -f --tail=200 backend
docker compose --env-file .env.prod -f docker-compose.prod.yml logs -f --tail=200 frontend

# restart one service
docker compose --env-file .env.prod -f docker-compose.prod.yml restart backend

# stop everything (data stays in volumes)
docker compose --env-file .env.prod -f docker-compose.prod.yml down
```

Health endpoints:

- `GET /healthz` — Nginx (frontend container);
- `GET /actuator/health` — backend, only inside the Docker network (not published).

Do not publish 8080 or 5432. If you need to inspect the database, use
`docker compose --env-file .env.prod -f docker-compose.prod.yml exec db psql -U marketplace -d marketplace`.

## 9. Environment variables

| Variable | Default | Purpose |
|---|---|---|
| `DOMAIN` | `marketplace.kbtu.kz` | Documentation / TLS examples |
| `HTTP_PORT` / `HTTPS_PORT` | `80` / `443` | Published ports of the frontend |
| `DB_NAME` / `DB_USER` | `marketplace` | PostgreSQL database and role |
| `DB_PASSWORD` | — | Required |
| `JWT_SECRET` | — | Required, 32+ characters |
| `JWT_TTL_MINUTES` | `60` | Backend token lifetime |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | empty | First admin, created on first start |
| `ALLOWED_EMAIL_DOMAIN` | `kbtu.kz` | Registration domain; empty = any |
| `FIREBASE_PROJECT_ID` | empty | Firebase token verification; empty = Firebase login off |
| `CORS_ORIGINS` | `http://localhost` | Comma-separated allowed origins |
| `VITE_FIREBASE_*` | empty | Inlined into the frontend bundle at build time |
| `BACKUP_KEEP_DAYS` | `14` | Daily database dumps to keep |

Backend defaults live in `student-marketplace/src/main/resources/application.yml`; the
production profile (`application-prod.yml`) disables Swagger, limits Actuator to `/health`,
removes stack traces from error responses and turns the rate limiter on.

## 10. Verify the deployment

```bash
# frontend loads
curl -I http://<server>/                      # 200, Content-Security-Policy present
curl -I http://<server>/some/deep/route       # 200 (SPA fallback to index.html)
curl -I http://<server>/api/client/listings   # 200 JSON from the backend

# backend is not reachable directly
curl --max-time 3 http://<server>:8080/actuator/health   # connection refused

# rate limit on the password endpoint (11th request within a minute)
for i in $(seq 1 11); do
  curl -s -o /dev/null -w "%{http_code}\n" -X POST http://<server>/api/auth/login \
    -H 'Content-Type: application/json' -d '{"email":"x@kbtu.kz","password":"wrong"}'
done
# expect: 401 x10, then 429
```

Manual smoke test: sign in with Firebase, create a listing with photos, edit it, mark it sold,
add it to favorites, sign out.

## 11. Local checks without Docker

Docker is not required to validate the code:

```powershell
# frontend
cd BIS
npm ci
npx tsc --noEmit
npm run build

# backend
cd student-marketplace
mvn verify
```

To reproduce the production frontend build locally:

```powershell
$env:VITE_BASE_PATH="/"
$env:VITE_API_BASE_URL="/api/client"
$env:VITE_USE_MOCK="false"
npm run build
```

The generated `dist/index.html` then references `/assets/...` instead of
`/student-marketplace/assets/...`.

## 12. Troubleshooting

| Symptom | Cause / fix |
|---|---|
| Backend exits with "app.jwt.secret must be at least 32 characters" | `JWT_SECRET` missing or too short in `.env.prod` |
| Frontend shows "API error 404" | Nginx is not proxying `/api/`; check `nginx/default.conf` and that `backend` is healthy |
| Google login popup is blocked by CSP | Add the Firebase auth domain to `frame-src`/`connect-src` in the CSP header |
| 502 Bad Gateway on `/api/` | Backend container is starting or unhealthy: `docker compose --env-file .env.prod -f docker-compose.prod.yml logs backend` |
| `db` restarts in a loop | Wrong `DB_PASSWORD` after changing it on an existing `pgdata` volume; the password is stored inside the volume |
| Changes to `.env.prod` do not apply | Recreate the service: `docker compose --env-file .env.prod -f docker-compose.prod.yml up -d --force-recreate backend` |
| Old frontend after deploy | `index.html` is cached by a proxy; the config sends `Cache-Control: no-cache` for it |

## 13. Security notes

See `SECURITY_REVIEW.md` for the full review. The short version:

- only 80/443 are published; PostgreSQL and the backend are internal;
- containers run with `no-new-privileges`; the backend runs as a non-root user;
- security headers (CSP, HSTS, X-Frame-Options, nosniff, Referrer-Policy, Permissions-Policy)
  are set by Nginx and by Spring Security;
- `/api/auth/login` and `/api/auth/register` are rate-limited twice (Nginx and the backend);
- Swagger and detailed Actuator endpoints are disabled in the `prod` profile;
- secrets come only from `.env.prod` and are never baked into images or committed.
